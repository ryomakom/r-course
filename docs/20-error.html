エラーとの付き合い方

実際の作業時間の半分は、エラーを読んで直す時間です。だから、ここが上手くなるといちばん効きます。

このページの中身

  • エラーが出ないのに、答えが変なとき

エラーは、怒られているのではない

Rを使いはじめて最初にくじけるのは、たいてい赤い文字です。何か悪いことをした気分になりますが、あれは怒っているのではなく、どこで何が分からなかったかを報告しているだけです。

エラーメッセージには、たいてい答えが書いてあります。英語なので読み飛ばしたくなりますが、そこをこらえて読むのがいちばんの近道です。日本語で読みたければ、そのままコピーして翻訳にかけるか、AIに貼りつけて聞けばいいのです（次の章）。

まず、2種類あるのを区別してください。

  • Error……処理が止まった。何も実行されていない。
  • Warning……処理は進んだが、気にしたほうがいいことがある。

Warningのほうが厄介です。動いてしまうからです。「NAが生まれました」「グループ化を解除しました」といった警告は、たいてい後で数字の狂いになって返ってきます。赤い字が出たら、Errorなのか Warningなのかを最初に見てください。

8割はこの五つ

私が出すエラーの大半は、この五つのどれかです。

1. object 'xxx' not found

Error: object 'df2020' not found

「df2020なんてものは知りません」。原因はほぼ二つです。

  • そのオブジェクトを作るコードを、まだ実行していない（R Markdownを上から順に流し直せば直ります）
  • 名前を打ち間違えている（df_2020 と df2020、population と poplation）

Environmentタブを見て、そこに目当ての名前があるか確かめるのが早いです。

2. could not find function "xxx"

Error in read_csv(...) : could not find function "read_csv"

「read_csvなんて関数は知りません」。library(tidyverse) を実行し忘れています。RStudioを開き直したあとにいちばんよく出ます。

read_excel なら library(readxl)、read_html なら library(rvest)。関数の名前でググれば、どのパッケージのものかはすぐ分かります。

3. 括弧やコンマの不足

Error in ... : unexpected ')'

コンソールに + が出たまま止まっている場合も、これです。閉じ括弧が足りていません。

RStudioは括弧の対応を色で教えてくれます。閉じ括弧にカーソルを合わせると、対応する開き括弧が光ります。長いコードで迷ったら、一度全部選んで Ctrl＋Shift＋A（コードを整形する）を押すと、階層のずれが見えて原因が分かることがあります。

4. 列の名前が違う

Error in `select()`: ! Can't select columns that don't exist.
✖ Column `poplation` doesn't exist.

これは親切なエラーで、どの列がないかまで書いてくれます。colnames() で正しい名前を確かめてください。

日本語の列名では、全角スペースと半角スペースの違いが犯人であることがよくあります。`地域 コード` の空白が半角なのか全角なのか、目では判別できません。colnames() の出力からコピーして貼りつけるのが確実です。

5. データ型が合っていない

Error in `bind_rows()`: ! Can't combine `..1$x` <double> and `..2$x` <character>.

10章でやったやつです。同じ名前の列なのに、片方が数値、片方が文字列。

直し方の手順

エラーが出たときの手順を決めておくと、パニックにならずに済みます。私はこうしています。

  1. メッセージの1行目を読む。どの関数で起きたかが書いてあります。
  2. その関数のところまでで、いったん止めて実行する。パイプを途中で切って、そこまでのデータがどうなっているかを見る。
  3. データの形を確かめる。glimpse() で列名と型を見る。nrow() で行数を見る。filter(is.na(...)) でNAを探す。
  4. それでも分からなければ、メッセージをそのまま検索する。自分のファイル名や列名は消して、汎用的な部分だけを貼る。
  5. AIに聞く。コードとエラーメッセージを両方貼るのがコツです。

パイプを途中で切って確かめる

これが最強のデバッグ方法です。長いコードが動かないとき、上から少しずつ実行します。

df2020 %>%
  select(地域, `A1101_総人口【人】`) %>%
  # rename(region = 地域) %>%      ← ここから下をコメントアウトして実行
  # mutate(rate = ...) %>%
  view()

行の頭に # をつけると、その行は無効になります（コメントアウト）。RStudioなら Ctrl＋Shift＋C で、選んだ範囲をまとめてコメントアウトできます。

上から1段ずつ足していって、どこで壊れるかを見つける。「ここまでは意図した形になっている」を確かめながら進むので、原因が必ず特定できます。

エラーが出ないのに、答えが変なとき

こちらのほうが、実は怖いです。コードは動いた。数字も出てきた。でも間違っている。記者にとっては、これが最悪の事故です。

予防するための確認を並べておきます。この講座でも各章で繰り返してきたことです。

確かめることコード
行数が想定と合っているかnrow()
合計が公表値と合っているかsummarize(sum(x))
種類の数が合っているか（47都道府県、289選挙区…）distinct(x) %>% nrow()
NAがいくつあるかfilter(is.na(x)) %>% nrow()
重複した行がないかcount(code) %>% filter(n > 1)
突合できなかったものはないかanti_join()
最大値・最小値がおかしくないかarrange(x) と arrange(desc(x))

とくに大事なのは、いちばん下の両端を見るという習慣です。人口がマイナスの自治体、100％を超える比率、1900年の日付。ありえない値は、たいてい端っこに出てきます。並べ替えて上下を見るだけで、多くの間違いに気づけます。

いちばん効く確認は、外の数字と突き合わせること

Rのなかだけで完結する確認には限界があります。いちばん強いのは、自分の集計を、公表されている数字と照らし合わせることです。

  • 都道府県別に集計したら、総務省が発表している都道府県の人口と比べる
  • 政党別に得票を集計したら、報道されている得票数と比べる
  • 年度別の件数を出したら、白書に載っている件数と比べる

合わなければ、必ず理由を突き止める。「四捨五入の差だろう」で済ませないこと。私の経験では、合わない理由の9割は自分のミスで、1割は公表値のほうの注記を読んでいないことでした。どちらにしても、理由が分かるまでは記事にしない。

最後の手段

どうしても分からないときは、いったん離れます。

私は、30分たっても進まなければ席を立つことにしています。翌朝コードを読んだら、== を = と書いていただけ、ということが本当によくあります。締め切りがあると難しいですが、詰まったまま粘るより早いことが多いです。

それでもダメなら、詳しい人に聞く。そのときは、

  • やろうとしていること（何を知りたいのか）
  • 書いたコード
  • 出たエラーメッセージ
  • データの形（glimpse() の結果）

の4点セットを渡すと、話が早く進みます。逆に「Rが動きません」だけでは、聞かれた側は何も答えられません。これは取材で相手に質問するときと同じですね。
