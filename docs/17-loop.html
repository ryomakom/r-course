第3部　データを集める

全国の裁判所を一気に集める

同じ形式のデータが、複数のページに分けて置かれています。読みたいURLのリストを作ってから、一気にデータを集めます。

このページの中身

  • 読みたいURLのリストを作る
  • for文の仕組み
  • 結果をまとめて保存する
  • 途中で止まらないようにする
  • 集まったものを整える

前回は東京地裁の管内にある裁判所について、リストをつくりました。でも裁判所はほかにもたくさんあって、そのすべてがcourts.go.jpというサイトのなかに散らばっています。

さっきみたいなコードを一つ一つ書けば、ぜんぶ取ることもできます。でもめんどくさいですよね。できれば少ないコードでまとめて取得したい。

読みたいURLのリストを作る

「各地の裁判所の所在地・電話番号等一覧」のページをみると、各地の裁判所のリストに飛べるリンクがたくさん張られています。まずはこのリンクを抜き出しましょう。この作業にもスクレイピングが使えます。こんなコードです。

"https://www.courts.go.jp/courthouse/map_tel/index.html" %>%
  read_html() %>%
  html_elements("div.module-sub-page-parts-table") %>%   # 前回と同じ名前の容器
  html_elements("a") %>%
  html_attr("href")

html_elements("a") は、その中にあるすべての <a> 要素、つまりハイパーリンクを取ってきなさい、という命令。前回は html_element() というコマンドを使いましたが、今回は取ってくるべき要素が2個以上あるので、複数形で html_elements() です。その上の行で容器を指定するところも同じで、このページには同じ名前の容器が八つあるので、ここでも複数形のhtml_elements() にしています。

最後の行にある html_attr("href") は、各リンクの href 属性、つまりURLの部分を抽出しなさい、という命令です。

HTMLをみてみると、リンクは <a href="./../../sapporo-h/about/syozai/index.html">所在地・代表電話</a> のように書かれています。画面に見えている「所在地・代表電話」という文字をクリックしたときに飛んでいく行き先を、html_attr("href") が拾ってくるわけです。

というわけで、必要なデータはひとまず取れました、が、余計なのが混じっていますし、URLとして完全なものにもなっていません。三つ、手を入れます。

"https://www.courts.go.jp/courthouse/map_tel/index.html" %>%
  read_html() %>%
  html_elements("div.module-sub-page-parts-table") %>%
  html_elements("a") %>%
  html_attr("href") %>%
  str_subset("syozai") %>%    # 所在地ページのURLだけを抽出
  url_absolute("https://www.courts.go.jp/courthouse/map_tel/index.html") %>%   # 絶対URLに変換
  unique()                    # 重複するURLを削除

このページには「窓口案内」のページなど、関係ないリンクも含まれています。狙っているリンクをいくつか開いて確認すると、URLに「syozai」という文字が含まれていることが分かります。なので、str_subset("syozai") という命令で、こういうURLだけにしぼります（知的財産高等裁判所だけはURLに「syozai」が入っていないので、このやり方では漏れてしまいますが、まあ今回はよしとしましょう）。

つぎに、取れてきたURLっぽい文字の並びを、完全なURLに変換します。元のURLを基準にした「相対URL」を、url_absolute() というコマンドを使って、そのまま使える「絶対URL」に変換するわけです。括弧内には、リンク元のページのURLを書いておけばOKです。

さらにURLが重複しているケースがあるので、余計なものを削るのが unique() というコマンドです。

うまくいったらオブジェクトに入れて、中身を見ておきましょう。

court_urls <- "https://www.courts.go.jp/courthouse/map_tel/index.html" %>%

  html_elements("a") %>%
  html_attr("href") %>%
  str_subset("syozai") %>%    # 所在地ページのURLだけを抽出
  url_absolute("https://www.courts.go.jp/courthouse/map_tel/index.html") %>%   # 絶対URLに変換
  unique()                    # 重複するURLを削除

for文の仕組み

リストができました。このURLの一つひとつにアクセスして、前回やったように、表を抜き出してtibbleに変えていくわけです。こういう反復作業をまとめていっぺんにやるのが「for文」です。

ただし、for文というのはちょっと複雑です。スクレイピングのことはいったん忘れて、どういう仕組みで動くのか、その基本を少しだけ見てみましょう。

alphabet <- c("あいうえお", "かきくけこ", "さしすせそ")

for (i in alphabet) {
  print(i)
}
[1] "あいうえお"
[1] "かきくけこ"
[1] "さしすせそ"

上のコードでは、まず「あいうえお」「かきくけこ」「さしすせそ」という三つの文字列を alphabet というオブジェクトに入れたうえで、for文を使ってそれを一つずつ表示するということをやっています。

c() は文字列を並べてひとかたまりにする関数で、06章の filter(prefecture %in% c("東京都", "大阪府")) でもう出てきていましたよね。

「i in alphabet」というのは、alphabet というオブジェクトの中にあるものを一つずつ順番に取り出して、それを「i」と呼ぶことにして、波括弧のなかの処理をやりなさい、という命令です。今回は print() というコマンドなので、三つの文字列が順番に表示されます。このときに使っている「i」という名前は慣習で、別に何でもかまいません。

ただ、よく見かけるのは、オブジェクトの中身そのものではなく、番号で回す書き方です。

for (i in seq_along(alphabet)) {
  print(alphabet[i])
}

seq_along(alphabet) は「alphabet の長さのぶんだけ、1、2……と数字を並べたもの」を返しなさい、という命令です。alphabet[1] と書けば、alphabet というオブジェクトにある1番目の要素、つまり「あいうえお」を取り出します。同様に alphabet[2] は「かきくけこ」です。つまり alphabet の中身をひとつひとつ取り出すには、alphabet[i] と書いて、iを一つずつ増やしていけばいいわけです。

結果をまとめて保存する

では、ここからはさっきの裁判所のデータに戻りましょう。

ひとつのURLにアクセスして処理することで、裁判所の所在地をまとめたtibbleがひとつ、できてきます。これをfor文で繰り返すわけですが、この際にはまず空っぽの入れ物をまず作ったうえで、できたtibbleを一つずつそこに足していく、という作業をやります。

# データの収容先として空っぽのtibbleを作っておく
court_contacts <- tibble()

# URLのリストに対して、さっきと同じように表を抽出してtibbleにするのを
# いっぺんに実行して、結果をまとめて保存する
for (i in seq_along(court_urls)) {
  table <- court_urls[i] %>%
    read_html() %>%
    html_elements("div.module-sub-page-parts-table table") %>%
    html_table()

  court_contacts <- bind_rows(court_contacts, table)

  Sys.sleep(2) # アクセス先に過剰な負荷をかけないため、次の動作までちょっとだけ待つ
}

だいじなのは下から2行目の bind_rows() のところ。これまで作った court_contacts というtibbleに、新しく読んだものを縦にくっつける。これを繰り返すと中身がどんどん増えていく、というわけです。空っぽのtibbleを最初に作るのを忘れると動かないので、そこは注意して下さい。

最後の Sys.sleep(2) は「2秒待て」という命令です。70ページ近くを2秒間隔で回すので、全部終わるまで3分ほどかかります。そのあいだRStudioは操作できないので、しばしお待ちを。

相手のサーバーに迷惑をかけない

コンピューターは何のためらいもなく、1秒間に何十回もアクセスします。これは相手のサーバーにとってはかなりの負荷で、場合によってはハッカーからの攻撃と区別がつきません。公開情報を機械的に取得しただけで問題になることもあります。だから Sys.sleep() というコマンドでわざとペースを落とすわけです。

2秒はあくまで例ですが、相手が小さな自治体のサーバーならもっと長くてもいいと思います。一度取ったものは手元に保存して、試行錯誤のたびに取り直さないようにする。何かあったときに相手の担当者が対応できない深夜や早朝は避ける。大量に取る必要があるなら、事前に連絡を入れる、といったことも必要でしょうか。

途中で止まらないようにする

スクレイピングの対象が何十件もあると、いくつかのページは他と作りが違ったりして、同じコードではデータを取れなかったりします。そうするとエラーが出るわけですが、何もしないと、for文はそこで止まってしまいます。

これを防ぐのが tryCatch() です。

court_contacts <- tibble()

for (i in seq_along(court_urls)) {
  tryCatch({

    table <- court_urls[i] %>%
      read_html() %>%
      html_elements("div.module-sub-page-parts-table table") %>%
      html_table()

    court_contacts <- bind_rows(court_contacts, table)
    message(str_c("成功", i, "/", length(court_urls)))

  }, error = function(e) {
    message(str_c("失敗", court_urls[i], "：", e$message))
  })

  Sys.sleep(2)
}

波括弧のなかの処理を試して、エラーが起きたら error = function(e) のほうに書いた処理をして、次のループに進みなさい、という命令です。e$message にはエラーの内容が入っているので、表示しておくと後で原因を追えます。

message() は途中経過を画面に出す関数です。「成功」と「失敗」を並べておけば、全部終わったあとに、どれが失敗したのかがひと目で分かります。失敗したものだけ、あとで個別に対処すればいいわけです。

いきなり全部まわさない

for文は基本、初めからうまく動くことなんてほぼありません（少なくとも私の場合は）。なので、上記の例であれば、for (i in seq_along(court_urls)) の部分をたとえば for (i in seq_along(court_urls[1:3])) として始めてみると良いと思います。こうすれば、70個近くある court_urls の要素のうちで最初の三つだけでループを試すことができます。こういう試験がうまくいってから、[1:3] のところを消して全体に挑戦するのが吉でしょう。

ページによって表の列名が違うのです。「裁判所名」となっているところもあれば「裁判所名（裁判所名をクリックすると地図が表示されます）」となっているところもある。郵便番号と所在地が「郵便番号・所在地」というひとつの列にまとまっているページもある。名前のない ...7 や ...8 は、HTMLでの表の書き方がほかと少し違うページから来たものです。bind_rows() は名前が違う列を別の列として扱いますから、列がやたら増えてしまっているわけです。

うーむ、めんどくさい。創造性は別のかたちで発揮してくださいよ……と愚痴りたくもなりますが、世の中のデータはだいたいこんなものです。なので「クリーニング」つまりデータのお掃除が大切になるわけで、ある意味ではこれがデータ分析の本丸といってもいいくらいです。

それから、多くのページの表には、16章の東京地裁と同じく「電話番号」という列が二つあります。bind_rows() は同じ名前の列を見つけると、電話番号...4、電話番号...5 のように後ろに番号をつけて区別します（ループを回しているあいだに「New names:」というメッセージがたくさん出るのはこのためです）。このあとのコードに出てくる 電話番号...4（担当）と 電話番号...5（番号）は、この2列のことです。

というわけで、ある程度クリーニングしましょう。

court_contacts_clean <- court_contacts %>%
  distinct() %>%
  mutate(name = if_else(is.na(裁判所名),
                        `裁判所名（裁判所名をクリックすると地図が表示されます）`,
                        裁判所名),
         post_code = if_else(is.na(郵便番号), `郵便番号・所在地`, 郵便番号),
         address = if_else(is.na(所在地), str_sub(`郵便番号・所在地`, 10), 所在地)) %>%
  filter(str_sub(name, 1, 4) != "裁判所名") %>%
  mutate(name = name %>%
           str_split_i("\n", 1) %>%
           str_remove_all("地図表示") %>%
           str_squish(),
         post_code = post_code %>%
           str_remove_all("〒") %>%
           str_remove_all("地裁"),
         post_code = str_c(str_sub(post_code, 1, 3), "-", str_sub(post_code, 5, 8))) %>%
  rename(contact_point = `電話番号...4`,
         phone = `電話番号...5`) %>%
  select(name, post_code, address, contact_point, phone)

これでも、まだ残っているものがあります。

  • 電話番号の列には、番号のかわりに「ダイヤルイン一覧」のようなリンクの文字だけが入っている行がかなりあります。ページに番号が書いてない裁判所が多いからです。

  • 名古屋家裁と大阪家裁の本庁、それに高松高裁は入っていません。HTMLでの表の書き方がほかのページと少し違っていたり、そもそも表がなかったりするためです。こういうのは手作業でやっちゃったほうが早い、かも。

どこまでやるかは、目的に応じて判断して下さい。照会の宛先リストにするだけなら住所と電話番号が正しければ十分ですが、地図に落とすなら住所の表記をそろえる必要がありますし、過去の一覧と突き合わせるなら裁判所名の表記を完全にそろえないといけません。きれいにする作業には終わりがないので、必要なところで止めるのがコツです。

そして、できあがったら何件か抜き出して、元のページと見比べておきましょう。70ページ近くあるうちの5ページ分くらいでいいので、目で確かめる。機械が集めたものだからといって、そのまま信じないほうがいいです。
