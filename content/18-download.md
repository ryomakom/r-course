## お題

選挙のデータを扱おうとすると、必ずこの壁にぶつかります。総務省は衆院選の市区町村別得票数を公表していますが、ファイルは都道府県ごとに分かれていて、リンクが一覧ページにずらっと並んでいます。

1つずつクリックして保存する。47回。しかも保存先を間違えたり、同じファイルを2回落としたりする。やりたくないですね。

ページに貼られているのが表ではなくファイルになっただけなので、やることはあまり変わりません。リンクの一覧を作って、1つずつ処理する。違うのは、tibbleに変える代わりにファイルとして保存する、という点です。

## httrでファイルを落とす

ファイルのダウンロードには、httrというパッケージが便利です。

```r
# install.packages("httr")
library(httr)
```

使い方はこうです。

```r
GET("https://www.soumu.go.jp/main_content/000979538.xlsx",
    write_disk("download/hokkaido.xlsx",
               overwrite = TRUE))
```

`GET()` は、そのURLに「このファイルを下さい」とお願いしなさい、という命令です。ブラウザがふだんやっているのと同じことですね。そして `write_disk()` が、返ってきたものをファイルとして保存する場所の指定。`overwrite = TRUE` は、同じ名前のファイルがすでにあったら上書きしていいですよ、という意味です。

パイプ演算子でつなぐこともできます。

```r
"https://www.soumu.go.jp/main_content/000979538.xlsx" %>%
  GET(write_disk("download/hokkaido.xlsx",
                 overwrite = TRUE))
```

:::warn 保存先のフォルダは先に作る
`download/` というフォルダが存在しないと、エラーになります。Rが勝手にフォルダを作ってはくれません。

RStudioの右下「Files」タブの「New Folder」で作ってもいいですが、コードで書いておくと、他の人が同じコードを動かすときにも困りません。

```r
dir.create("download", showWarnings = FALSE)
```

`showWarnings = FALSE` は「すでにあっても文句を言うな」という指定です。
:::

:::note read_csvで直接読むのとの違い
[04章](04-import.html)で、`read_csv("https://……")` と書けばウェブ上のファイルを直接読めると書きました。それでいい場面も多いのですが、いったんファイルとして手元に落としたほうがいいこともあります。

まずExcelファイルの場合、`read_excel()` はURLを直接読めないので、落とすしかありません。それに何度も試行錯誤するなら、落としておけば、そのたびに相手のサーバーを叩かずに済みます。

でも、いちばん大きいのは元データの証拠が残ることでしょう。役所のサイトのファイルは、しれっと差し替えられることがあります。数字が訂正されたのに、公表日はそのままだったりする。落とした日付をファイル名に入れて保存しておけば、記事を書いた時点で公表されていた数字はこれだ、と示せるわけです。私は `download/20250610_hokkaido.xlsx` のように日付を頭につけて保存しています。
:::

## リンクの一覧をつくる

さて、ここから本番です。一覧ページに並んだリンクを、全部拾ってきます。[前章](17-loop.html)と同じで、rvestで `html_attr("href")` を取ります。

```r
excel_urls <- "https://www.soumu.go.jp/senkyo/senkyo_s/data/shugiin50/shikuchouson.html" %>%
  read_html() %>%                    # そのページのHTMLのコードを読み込む
  html_node("table.tableList") %>%   # 最初にある <table class="tableList"> 要素を取得
  html_elements("a") %>%             # その中にあるすべての <a> 要素を取得
  html_attr("href") %>%              # 各リンクの href 属性（URL部分）を抽出
  str_c("https://www.soumu.go.jp", .)
```

`html_node()`（単数形）は最初に見つかった1つだけを、`html_nodes()`（複数形）は該当するもの全部を返します。ここでは表が1つだけなので単数形を使っています。

取れたら、必ず中身を目で確かめて下さい。

```r
excel_urls
length(excel_urls)
```

47都道府県分（＋比例代表など）のURLが、ちゃんとした形で並んでいますか。ここで `NA` が混ざっていたり、`https://www.soumu.go.jphttps://...` のような妙な形になっていたら、次に進んでもうまくいきません。

:::tips 相対パスの落とし穴
`str_c("https://www.soumu.go.jp", .)` は、リンクが `/senkyo/...` のような形（頭にスラッシュがある相対パス）であることを前提にしています。

でも、ページによってはリンクが最初から `https://` で始まっていたり、`../data/...` のような形だったりします。前者にドメイン名をくっつけると、当然おかしなURLになります。

安全に書くなら、rvestの `url_absolute()` を使う手があります。

```r
html_attr("href") %>%
  url_absolute("https://www.soumu.go.jp/senkyo/senkyo_s/data/shugiin50/shikuchouson.html")
```

もとのページのURLを教えると、相対パスでも絶対パスでも、正しい完全なURLに直してくれます。
:::

## 全部落とす

あとはfor文に入れるだけです。今回はtibbleにためるのではなく、1周ごとにファイルを保存します。

```r
for (i in seq_along(excel_urls)) {
  # ファイル名をリンクの末尾から取得
  filename <- excel_urls[i] %>%
    basename() %>%
    str_c("download/", .)

  # ローカルに保存
  excel_urls[i] %>%
    GET(write_disk(filename,
                   overwrite = TRUE))

  Sys.sleep(2)   # アクセス先に過剰な負荷をかけないため、次の動作までちょっとだけ待つ
}
```

`basename()` は、URLやファイルパスから最後の部分（＝ファイル名）だけを取り出す関数です。`https://www.soumu.go.jp/main_content/000979538.xlsx` なら `000979538.xlsx` が返ってきます。それに `download/` をくっつけて、保存先のパスにしています。

## 途中で止まらないようにする

47回のうち1回でもエラーが出ると、for文はそこで止まります。リンク切れが1つあるだけで最後まで走らないのは困るので、前章と同じように `tryCatch()` で囲みましょう。

```r
for (i in seq_along(excel_urls)) {
  tryCatch({
    # ファイル名をリンクの末尾から取得
    filename <- excel_urls[i] %>%
      basename() %>%
      str_c("download/", .)

    # ローカルに保存
    GET(excel_urls[i], write_disk(filename, overwrite = TRUE))

    message(sprintf("✅ %s をダウンロードしました。", filename))

  }, error = function(e) {
    message(sprintf("⚠️ %s のダウンロード中にエラーが発生しました: %s",
                    excel_urls[i], e$message))
  })

  Sys.sleep(2)   # サーバーへの負荷軽減のため待機
}
```

`sprintf()` は文字を組み立てる関数で、`%s` のところに後ろで指定したものが入ります。`str_c()` でも同じことができますが、こういう「メッセージのひな型」を書くときは `sprintf()` のほうが読みやすいと思います。

全部終わったら、落ちてきたファイルを数えて確かめます。

```r
list.files("download")
length(list.files("download"))
```

リンクの数と、落ちてきたファイルの数は合っていますか。合っていなければ、`⚠️` が出た行を探して下さい。

:::warn ダウンロードできたのに、中身がHTMLのとき
たまに、`GET()` は成功したのにファイルを開けない、ということが起きます。中身をメモ帳で開いてみると、Excelではなく「お探しのページは見つかりません」というHTMLが入っている。

これは、リンク切れや、URLの組み立てを間違えたときに起きます。サーバーは「そんなファイルはない」というページを返し、httrはそれをそのまま保存しただけなのです。

ファイルサイズを見ると分かります。

```r
list.files("download", full.names = TRUE) %>%
  file.info() %>%
  arrange(size)
```

やたら小さいファイル（数キロバイト）があったら、それが犯人です。
:::

## 直接読めないページもある

ここでもう一つ、実務でよく出会う話をしておきます。

たとえば防衛装備庁が公表している契約実績のページ。ここからExcelファイルを落とそうとして、同じコードを書いてもうまくいかないことがあります。ページを直接読もうとするとなぜかうまく行かないのです。

そういうときは、あきらめて手作業を1回だけ挟みます。ブラウザでそのページを開いて、「名前を付けて保存」でHTMLファイルとして手元に保存する。そして、そのファイルを読むのです。

```r
atla_files <- "atla.html" %>%
  read_html() %>%
  html_nodes("div.article-main__group") %>%
  html_elements("a") %>%
  html_attr("href")
```

`read_html()` は、URLでもローカルのファイルでも同じように読めます。あとの処理はまったく同じです。

:::note なぜ直接読めないのか
理由はいくつか考えられます。ページの中身がJavaScriptで後から作られていて、`read_html()` はJavaScriptを動かさないので空っぽのページを読んでしまう、というのがよくあるパターンです。サーバーがブラウザ以外からのアクセスをはじいていることもありますし、認証やCookieが必要な場合もあります。

きちんと対処する方法もあるらしいのですが（`httr` でブラウザのふりをする、`chromote` でブラウザごと動かす、など）、1回だけの作業なら、手で保存するのがいちばん早いです。自動化にこだわって半日つぶすくらいなら、手で3分やって次に進みましょう。毎月やる作業になったら、そのときに考えればいいわけです。
:::

落としたファイルを読み込む段になると、次の壁が待っています。役所のExcelは、そのままでは読めない形をしていることが多いのです。次の章では、その「神エクセル」に立ち向かいます。
