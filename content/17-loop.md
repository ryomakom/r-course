前回は東京地裁の管内にある裁判所について、リストをつくりました。でも裁判所はほかにもたくさんあって、そのすべてがcourts.go.jpというサイトのなかに散らばっています。

さっきみたいなコードを一つ一つ書けば、ぜんぶ取ることもできます。でもめんどくさいですよね。できれば少ないコードでまとめて取得したい。

## 読みたいURLのリストを作る

[https://www.courts.go.jp/courthouse/map_tel/index.html](https://www.courts.go.jp/courthouse/map_tel/index.html)

このページをみると、各地の裁判所のリストに飛べるリンクがたくさん張られています。まずはこのリンクを抜き出しましょう。この作業にもスクレイピングが使えます。こんなコードです。

```r
"https://www.courts.go.jp/courthouse/map_tel/index.html" %>%
  read_html() %>%
  html_elements("div.module-sub-page-parts-table") %>%   # 前回と同じ名前の容器
  html_elements("a") %>%
  html_attr("href")
```

`html_elements("a")` は、その中にあるすべての `<a>` 要素、つまりハイパーリンクを取ってきなさい、という命令。前回は `html_element()` というコマンドを使いましたが、今回は取ってくるべき要素が2個以上あるので、複数形で `html_elements()` です。その上の行で容器を指定するところも同じで、このページには同じ名前の容器が8つあるので、`html_elements()` にしています。

その次の行にある `html_attr("href")` は、各リンクの `href` 属性、つまりURLの部分を抽出しなさい、という命令です。

HTMLをみてみると、リンクは `<a href="./../../sapporo-h/about/syozai/index.html">所在地・代表電話</a>` のように書かれています。画面に見えているのは「所在地・代表電話」という文字ですが、`html_attr("href")` が拾ってくるのは行き先のほうだ、というわけです。

実行すると、URLらしきものがずらっと並んで返ってきます。でも余計なのが混じっていますし、URLとして完全なものにもなっていません。三つ、手を入れます。

```r
"https://www.courts.go.jp/courthouse/map_tel/index.html" %>%
  read_html() %>%
  html_elements("div.module-sub-page-parts-table") %>%
  html_elements("a") %>%
  html_attr("href") %>%
  str_subset("syozai") %>%    # 所在地ページのURLだけを抽出
  url_absolute("https://www.courts.go.jp/courthouse/map_tel/index.html") %>%   # 絶対URLに変換
  unique()                    # 重複するURLを削除
```

このページには「窓口案内」のページなど、関係ないリンクも含まれています。狙っているリンクをいくつか開いて確認すると、URLに「syozai」という文字が含まれていることが分かります。なので、`str_subset("syozai")` という命令で、こういうURLだけにしぼります（ただし知的財産高等裁判所だけは、URLに「syozai」が入っていないので、このやり方では漏れてしまいます）。

つぎに、取れてきたURLっぽい文字の並びを、完全なURLに変換します。元のURLを基準にした「相対URL」を、`url_absolute()` というコマンドを使って、そのまま使える「絶対URL」に変換するわけです。括弧内には、リンク元のページのURLを書いておけばOKです。

さらにURLが重複しているケースがあるので、余計なものを削るのが `unique()` というコマンドです。

うまくいったらオブジェクトに入れて、中身を見ておきましょう。

```r
court_urls <- "https://www.courts.go.jp/courthouse/map_tel/index.html" %>%
  read_html() %>%
  html_elements("div.module-sub-page-parts-table") %>%
  html_elements("a") %>%
  html_attr("href") %>%
  str_subset("syozai") %>%    # 所在地ページのURLだけを抽出
  url_absolute("https://www.courts.go.jp/courthouse/map_tel/index.html") %>%   # 絶対URLに変換
  unique()                    # 重複するURLを削除

court_urls
```

## for文の仕組み

リストができました。このURLの一つひとつにアクセスして、前回やったように、表を抜き出してtibbleに変えていくわけです。こういう反復作業をまとめていっぺんにやるのが「for文」です。

for文というのはちょっと複雑なので、スクレイピングのことはいったん忘れて、どういう仕組みで動くのか、その基本を少しだけ見てみましょう。

```r
alphabet <- c("あいうえお", "かきくけこ", "さしすせそ")

for (i in alphabet) {
  print(i)
}
```

```console
[1] "あいうえお"
[1] "かきくけこ"
[1] "さしすせそ"
```

まず、「あいうえお」「かきくけこ」「さしすせそ」という三つの文字列を `alphabet` というオブジェクトに入れたうえで、for文を使ってそれを一つずつ表示するということをやっています。

`c()` は文字列を並べてひとかたまりにする関数で、[06章](06-strings-filter.html)の `filter(prefecture %in% c("東京都", "大阪府"))` でもう出てきていましたよね。

「`i in alphabet`」というのは、`alphabet` というオブジェクトの中にあるものを一つずつ順番に取り出して、それを「i」と呼ぶことにして、波括弧のなかの処理をやりなさい、という命令です。今回は `print()` というコマンドなので、三つの文字列が順番に表示されます。このときに使っている「i」という名前は慣習で、別に何でもかまいません。

実務でよく見かけるのは、中身そのものではなく番号で回すこの書き方です。

```r
for (i in seq_along(alphabet)) {
  print(alphabet[i])
}
```

`seq_along(alphabet)` は「`alphabet` の長さのぶんだけ、1、2……と数字を並べたもの」を返しなさい、という命令です。`alphabet[1]` と書けば、`alphabet` というオブジェクトにある1番目の要素、つまり「あいうえお」を取り出します。同様に `alphabet[2]` は「かきくけこ」です。つまり `alphabet` の中身をひとつひとつ取り出すには、`alphabet[i]` と書いて、iを一つずつ増やしていけばいいわけです。

## 結果をまとめて保存する

for文の本当の使いどころは、結果をどこかにためていくことです。1周ごとに1ページ分の表が取れるので、それを一つの入れ物に足していきます。入れ物は先に空っぽのものを用意しておきます。

```r
# データの収容先として空っぽのtibbleを作っておく
court_contacts <- tibble()

# URLのリストに対して、さっきと同じように表を抽出してtibbleにするのを
# いっぺんに実行して、結果をまとめて保存する
for (i in seq_along(court_urls)) {
  table <- court_urls[i] %>%
    read_html() %>%
    html_elements("div.module-sub-page-parts-table table") %>%
    html_table()

  court_contacts <- bind_rows(court_contacts, table)

  Sys.sleep(2) # アクセス先に過剰な負荷をかけないため、次の動作までちょっとだけ待つ
}
```

だいじなのは下から2行目の `bind_rows()` のところ。これまで作った `court_contacts` というtibbleに、新しく読んだものを縦にくっつける。これを繰り返すと中身がどんどん増えていく、というわけです。空っぽのtibbleを最初に作るのを忘れると動かないので、そこは注意して下さい。

最後の `Sys.sleep(2)` は「2秒待て」という命令です。70ページ近くを2秒間隔で回すので、全部終わるまで3分ほどかかります。そのあいだRStudioは操作できないので、しばしお待ちを。

:::warn 相手のサーバーに迷惑をかけない
コンピューターは何のためらいもなく、1秒間に何十回もアクセスします。これは相手のサーバーにとってはかなりの負荷で、場合によってはハッカーからの攻撃と区別がつきません。公開情報を機械的に取得しただけで問題になることもあります。だから `Sys.sleep()` というコマンドでわざとペースを落とすわけです。

2秒はあくまで例ですが、相手が小さな自治体のサーバーならもっと長くてもいいと思います。一度取ったものは手元に保存して、試行錯誤のたびに取り直さないようにする。何かあったときに相手の担当者が対応できない深夜や早朝は避ける。大量に取る必要があるなら、事前に連絡を入れる、といったことも必要でしょうか。
:::

## 途中で止まらないようにする

3分間も「終わった」と言ってくれないと、動いているのか固まっているのか分かりません。それに70ページ近くもあれば、たいてい一つか二つは作りが違って失敗します。ふつうのfor文はエラーが出るとそこで止まってしまうので、23個目で失敗すると24個目以降には進みません。

これを防ぐのが `tryCatch()` です。

```r
court_contacts <- tibble()

for (i in seq_along(court_urls)) {
  tryCatch({

    table <- court_urls[i] %>%
      read_html() %>%
      html_elements("div.module-sub-page-parts-table table") %>%
      html_table()

    court_contacts <- bind_rows(court_contacts, table)
    message(str_c("○ ", i, "/", length(court_urls)))

  }, error = function(e) {
    message(str_c("× ", court_urls[i], "：", e$message))
  })

  Sys.sleep(2)
}
```

波括弧のなかの処理を試して、エラーが起きたら `error = function(e)` のほうに書いた処理をして、次の周に進みなさい、という命令です。`e$message` にはエラーの内容が入っているので、表示しておくと後で原因を追えます。

`message()` は途中経過を画面に出す関数です。○と×を並べておけば、全部終わったあとに、どれが失敗したのかがひと目で分かります。失敗したものだけ、あとで個別に対処すればいいわけです。

:::tips いきなり全部まわさない
for文は基本、初めからうまく動くことなんてほぼありません（少なくとも私の場合は）。なので、上記の例であれば、`for (i in seq_along(court_urls))` の部分をたとえば `for (i in seq_along(court_urls[1:3]))` として始めてみると良いと思います。こうすれば、70個近くある `court_urls` の要素のうちで最初の三つだけでループを試すことができます。こういう試験がうまくいってから、`[1:3]` のところを消して全体に挑戦するのが吉でしょう。
:::

## 集まったものを整える

さて、集まったtibbleを見てみましょう。……なかなかひどい状態です。

```r
court_contacts %>% colnames()
court_contacts %>% nrow()
```

ページによって表の列名が違うのです。「裁判所名」となっているところもあれば「裁判所名（裁判所名をクリックすると地図が表示されます）」となっているところもある。そもそも列名がなくて `X1` `X2` になっているページもある。`bind_rows()` は名前が違う列を別の列として扱いますから、列がやたら増えてしまっているわけです。

それから、多くのページの表には、[16章](16-scraping.html)の東京地裁と同じく「電話番号」という列が二つあります。`bind_rows()` は同じ名前の列を見つけると、`電話番号...4`、`電話番号...5` のように後ろに番号をつけて区別します（ループを回しているあいだに「New names:」というメッセージがたくさん出るのはこのためです）。このあとのコードに出てくる `電話番号...4`（担当）と `電話番号...5`（番号）は、この2列のことです。

ここからが、地味ですが本番です。ある程度クリーニングしましょう。

```r
court_contacts <- court_contacts %>%
  filter(is.na(裁判所名) | 裁判所名 != "裁判所名") %>%
  mutate(裁判所名 = ifelse(
    !is.na(`裁判所名（裁判所名をクリックすると地図が表示されます）`),
    `裁判所名（裁判所名をクリックすると地図が表示されます）`,
    裁判所名)) %>%
  mutate(裁判所名 = ifelse(!is.na(X1), X1, 裁判所名)) %>%
  mutate(郵便番号 = ifelse(!is.na(X2), X2, 郵便番号)) %>%
  mutate(所在地 = ifelse(!is.na(X3), X3, 所在地)) %>%
  mutate(電話番号...4 = ifelse(!is.na(X4), X4, 電話番号...4)) %>%
  mutate(電話番号...5 = ifelse(!is.na(X5), X5, 電話番号...5)) %>%
  mutate(所在地 = ifelse(
    !is.na(`郵便番号・所在地`),
    `郵便番号・所在地`,
    所在地)) %>%
  mutate(郵便番号 = ifelse(
    is.na(郵便番号),
    str_sub(所在地, 2, 9),
    郵便番号)) %>%
  mutate(所在地 = ifelse(
    str_detect(所在地, "〒"),
    str_sub(所在地, 10, 100),
    所在地)) %>%
  rename(name = 裁判所名,
         post_code = 郵便番号,
         address = 所在地,
         contact_point = 電話番号...4,
         phone = 電話番号...5) %>%
  select(name, post_code, address, contact_point, phone)
```

長いですが、使っているのはこれまでに覚えた関数だけです。やっていることも単純で、`ifelse()`（[14章](14-point.html)で使った `if_else()` とほぼ同じもの）を使って「こっちの列が空っぽでなければ、そっちの中身を採用する」を延々と繰り返しているだけです。

1行目の `filter()` は、表の見出し行がデータとして混ざり込んだものを捨てています。見出しなのに中身として読まれた行では、裁判所名の列に「裁判所名」という文字が入っているわけです。

後半では、`所在地` の列に「〒700-0807岡山市北区南方……」のように郵便番号ごと入っているページ（岡山地裁）に対応しています。`str_sub(所在地, 2, 9)` で2文字目から9文字目、つまり郵便番号の部分を取り出し、`str_sub(所在地, 10, 100)` で10文字目以降、つまり住所の部分を取り出している、という具合です。

どこまでやるかは、目的に応じて判断して下さい。照会の宛先リストにするだけなら住所と電話番号が正しければ十分ですが、地図に落とすなら住所の表記をそろえる必要がありますし、過去の一覧と突き合わせるなら裁判所名の表記を完全にそろえないといけません。きれいにする作業には終わりがないので、必要なところで止めるのがコツです。

そして、できあがったら何件か抜き出して、元のページと見比べておきましょう。70ページ近くあるうちの5ページ分くらいでいいので、目で確かめる。機械が集めたものだからといって、そのまま信じないほうがいいです。

最後に書き出して、おしまいです。

```r
court_contacts %>%
  write_excel_csv("output/裁判所連絡先.csv")
```
