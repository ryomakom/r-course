つぎに、複数のデータを合体させるための関数を学んでいきましょう。まずは一番シンプルな、`bind_rows()` という関数から。

これまでは2020年の国勢調査データを使っていましたが、ここからはさらに2000年、2005年、2010年、2015年のデータも使っていきます。それぞれのデータを読み込んでいきましょう。

:::data この章で使うデータ
[人口データ2015.csv](files/人口データ2015.csv)

[人口データ2010.csv](files/人口データ2010.csv)

`data` フォルダに入れてください。2000年と2005年のぶんは[10章](10-datatype.html)で使います。

## 同じ統計でもデータの形式がいろいろ違う

では、まずは2015年から。2020年のときと同じように、`read_csv()` 関数を使って読んでみます。

```r
read_csv("data/人口データ2015.csv", skip = 8)
```

```out outputs/08-bad-skip.txt
```

あれ? 列名が何かおかしいですね。たとえば4列目の名前が「北海道 札幌市 豊平区」となってしまっています。データの「中身」になるべきものが、列の名前になってしまっているようです。なぜでしょうか。ファイルをExcelなどで開いて、確認してみましょう。

```file outputs/08-csv2015-head.txt
```

こうなっています。2020年の人口データのファイルでは、1～8行目にはあまり意味のない情報が入っていたので、`skip=8` と指定することで、8行分を飛ばして読み込みました。でもこのファイルでは、意味のない情報は1～2行目にしか入っていません。つまり3行目以降を読み込むのが正解だったのです。

```r
read_csv("data/人口データ2015.csv", skip = 2)
```

## 文字コードでつまずく

次に2010年のデータも読み込んでみます。Excelで確認すると、5行目まで飛ばして読めばよさそうです。やってみましょう。

```r
read_csv("data/人口データ2010.csv", skip = 5)
```

あれ?　やっぱりうまく行きませんね。

```out outputs/08-encoding-error.txt
```

こんなふうに叱られました。読めない文字があると言っています（`input string 1 is invalid UTF-8` と出ることもあります。文言はRやパッケージのバージョンによって変わりますが、言っていることは同じです）。文字コードがUTF-8じゃないから読み込めないようです。日本語だと、可能性が高い文字コードはShift-JISです。そこで、文字コードを指定して読み込みましょう。

```r
read_csv("data/人口データ2010.csv", skip = 5, locale = locale(encoding = "CP932"))
```

これでうまく行きました。

:::warn 文字コードの話（役所のデータを扱うなら避けられません）
文字コードとは、文字をコンピューターの中で数字として表すときの取り決めのことです。同じ「東」という字でも、取り決めが違えば違う数字になります。だから、書いたときの取り決めと読むときの取り決めが食い違うと、文字化けしたりエラーになったりします。

役所が出すcsvでよく出会うのは次の2つです。

- **UTF-8**……いまの世界標準。`read_csv()` はこれを前提にしています。
- **Shift-JIS**（Windows拡張版の名前がCP932）……日本のWindowsで長く使われてきたもの。役所のcsvにはまだ多い。

`invalid UTF-8` と言われたら、`locale = locale(encoding = "CP932")` を付けてみる。逆にShift-JISだと思って指定したのに化けるなら、外してみる。この2択でほぼ解決します。

なぜ「Shift-JIS」ではなく「CP932」と書くのかというと、CP932のほうが対応している文字の範囲が広く、Windowsで作られたファイルを読むならこちらが確実だからです。私はいつもCP932と書いています。
:::

## bind_rows——縦に積み上げる

ではいよいよ、`bind_rows()` 関数を使って、読み込んだデータを合体させていきます。

```r
df <- bind_rows(df2020,
                read_csv("data/人口データ2015.csv", skip = 2),
                read_csv("data/人口データ2010.csv", skip = 5,
                         locale = locale(encoding = "CP932")))
```

`bind_rows()` 関数の括弧のなかでは、すでに読み込み済みの `df2020` と、2015年と2010年のデータをそれぞれ `read_csv()` 関数で読み込んだもののみっつがコンマでつながっています。これで合体させたものを、`df` というオブジェクトに代入しているわけです。

`bind_rows()` がやっているのは、**列の名前を見比べて、同じ名前の列を同じ列に積み上げる**という作業です。だから列の並び順が違っていても平気ですし、片方にしかない列があっても、足りないほうはNAで埋めて合体してくれます。

:::tips 何行になったか、必ず確かめる
```r
df %>% nrow()
```

合体前のみっつを足した行数と合っていますか。また、年ごとの行数も見ておきましょう。

```r
df %>% count(調査年)
```

```out outputs/08-count-year.txt
```

みっつの年が、それぞれ1916行。市区町村と政令市の区を合わせた数なので、これで正しそうです。

`count()` は「その列の値ごとに何行あるか」を数えてくれる関数で、`group_by` ＋ `summarize(n())` の省略版です。
:::

## 列の名前をそろえる

さて、この `df` というtibbleには余計な列がたくさんあったり、列の名前が長ったらしいうえに日本語なので扱いにくかったりします。シンプルなものに変えてみましょう。`df2020` のときにやったのと基本は同じですが、今回は複数の年のものが混じっているのが大きな違いです。この年のデータと地域名、それぞれの総人口という3つの列に絞りましょう。

```r
df_simple <- df %>%
  select(調査年,
         地域,
         `A1101_総人口【人】`) %>%
  rename(year = 調査年,
         region = 地域,
         population = `A1101_総人口【人】`)
```

これで、「年」「自治体名」「人口」の3列だけのすっきりしたデータになりました。

:::warn bind_rowsがうまくいかないとき
`bind_rows()` は便利ですが、つまずきやすいのは次のふたつです。

1. **列名が微妙に違う。** 「地域 コード」と「地域コード」のように空白の有無が違うだけでも、別の列として扱われます。結果として、片方がNAで埋まった不気味なtibbleができあがります。合体したら `colnames()` で列名を眺め、似た名前の列が2つできていないか確かめてください。
2. **データ型が違う。** 同じ名前の列なのに、片方は数値、片方は文字列だと、そもそもエラーで止まります。これは[10章](10-datatype.html)で正面から扱います。

1番のほうはエラーは出ませんが、中身を見るとぜんぜんうまくいっていない。こちらのほうが厄介です。
:::
